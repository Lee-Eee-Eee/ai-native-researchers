# AI Native Researchers

接手项目时，先读现有首页、最近一次阶段记录和实际产物。用一句话写清研究者想知道什么，以及什么观测能回答。比较两个解释时，指出它们在哪个条件下会给出不同预测。沿用项目既有的文件名、引文键、运行环境和发布范围。用户只要求整理一项实验时，从那项实验开始。

默认通过文件、命令行、连接器和本地 API 在后台工作。遇到软件要求用户批准的原生授权，把动作、用途和当前进度告诉用户。让用户决定何时处理弹窗，继续做可独立完成的工作。仅在用户要求使用桌面时才接管窗口。

若要设计整组的研究方式，读[模型参与研究时如何分工](references/model-generation.md)。它从选题、设计比较讲到交付，给出独立复核和检验自动化收益的办法。遇到数据版本、集群调度、模型追踪或成果归档等具体困难时，根据[工具选择表](references/tool-choices.md)选一项接到现有流程中。

## 建立项目入口

- 用一个个人 Obsidian 主库日常审阅。各项目有自己的入口，各阶段笔记只保留一份可编辑原稿。首页链接当前问题、最新结论、逐例证据、原始结果和下一步。需要独立交接或与另一组人单独共享整套笔记时，再单独建库。
- 已有项目接入主库时，先查首页和阶段页的相对链接、旧入口、手写批注及插件输出目录。按[主库接入与验收](references/review-vault.md)选取需要审阅的原稿，在主库验证引用能打开、编辑能写回。
- 代码和轻量参数用 Git。大数据、模型权重或受限材料沿用其存储位置，给阶段记录留下检索所需的数据版本、稳定标识或校验值。

## 结束一轮实验

1. 找到真正执行过的命令、输入版本、对照条件和输出表。找到一条会改变判断的失败样本或误差最大的样本，复核它对总体结论的影响。涉及模型比较时核对划分单位、可见输入、先验和评价窗口。
2. 按项目已有顺序续写。采用编号的项目可用同号两页，例如 `017_两个测点能否分开两种状态.md` 与 `017a_逐例结果.md`。正文具体说谁在什么条件下变好了多少，配套页给出分母、单位、逐例结果、版本和复算办法。保留原先的判断，若证据改变则另记日期。
3. 把新页接回首页。读者从一句结论应当能走到结果表，再找到产生该表的命令。优先由助手根据真实产物填写阶段描述，调用[自动收尾命令](references/automation.md)生成两页、指纹和首页入口。手工套用[阶段模板](assets/milestone/)时，改成编号文件名后同步更新两处互链，并沿两条链接各走一次。

## 把论文接到判断

从正文中一个需要引用的判断出发。在共用的 Zotero 文库按 DOI 或题名、作者与年份查找已有条目；多个项目要用同一篇论文时，把原条目加入相应分类。把论文的相关章节、图表或实验条件写在对应判断旁，说明它支持哪句话。用户想在 Obsidian 审阅整组论文时，先用[后台分类同步](references/library-sync.md)批量建立目录和阅读页。需要原文批注时，按[文献与笔记](references/literature.md)接入 ZotLit，区分导入区和研究者手写区。读回目标分类或笔记后再报告完成。

## 把反复运行的步骤接起来

单一脚本若已足够，保留其入口。当做出一个结果需要多道加工、多人重复操作或反复更换输入时，选一张真正需要交付的图或表，从它向前追到原始输入。把每一步的输入、脚本、参数和输出写成 Snakemake 规则。给规则加入可判定的质量条件，例如行数、独立组数、单位、重复键或对照是否配齐。

从小样本开始，在隔离环境试跑，随后改一个输入检验重算范围。运行与留证的细节见[复算与交接](references/reproduction.md)。新项目可复制[最小工作流](assets/snakemake-starter/)。

## 交接

从干净目录或明确记录的已有环境，做一次成本合适的复核。写下跑了什么、验证到哪项输出、还有哪个问题需要新证据。若接下来要发表，只把本次明确要公开的文件放进待推送清单，逐项核对项目材料、个人配置、文献版权及仓库可见性。
