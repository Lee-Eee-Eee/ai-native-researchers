# 在个人主库审阅项目

项目首页、编号结论页、逐例证据页和阅读笔记适合在同一个 Obsidian 窗口审阅。原始采集、仿真输出、虚拟环境和模型权重沿用各项目的存储位置。Git 仓库按项目划分，主库按谁需要一起读写这些笔记来划分。

## 接入已有项目

1. 先打开最近一条结论，沿着链接找到逐例表和引用的论文。记下文件所在位置，以及原稿是由谁、用什么程序写入的。查看主库同名目录中已有的手写笔记、模板和入口，遇到同名文件先读内容。
2. 新项目可直接在主库的项目目录维护原稿。已有项目若依赖原目录跑脚本，保留原稿及运行路径。需要在主库直接编辑外部笔记时，可在本机将专放笔记的目录接入主库；Windows 可用目录联接。逐个核对目标，保持它们互不包含，确认同一批原稿只有一套同步程序写入。Obsidian 官方列出了这些链接在文件监看、同步和跨设备使用时的限制。[目录链接的适用条件](https://obsidian.md/help/symlinks)
3. 从主库入口再走一遍原有相对链接。像 `../results/score.csv` 这样的引用会从新入口按层级寻找结果。只给需要阅读的证据接上可用路径，数据在外部存储时给出可打开的归档地址。遇到原稿分散、无法安全映射的页面，先保留原入口并写清它会在哪个库打开。
4. 在主库核对要用的插件、启用状态和笔记落点。多个项目使用同一个 ZotLit 时，把本次项目的分类和阅读目录配对，保留主库原有配置和其他项目的输出位置。用一个真实条目刷新两次，检查它写到了预期目录，手写段落仍在。[Obsidian 的库级设置](https://obsidian.md/help/data-storage)

## 怎样算接好了

在主库从项目首页打开阶段判断，再打开逐例表和论文。用一份临时测试笔记，从主库写入一句话，在项目原路径读回；从原路径更新后，再从主库读回。清除测试笔记。涉及编辑器原子替换或自动生成的页面时，按实际写入方式再试一次。目录链接、硬链接和文件副本在同名文件被替换后可能表现不同。

保留现有独立库和旧入口，直到主库通过上述检查。用户指定保留独立库时，旧入口继续可用。交接给新团队时，再把所需的编号笔记、证据和文献链接纳入它的共享范围。
