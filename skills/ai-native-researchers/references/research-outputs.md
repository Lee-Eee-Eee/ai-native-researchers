# 从阶段证据到科研图、汇报与论文

从项目首页打开同号的阶段判断与证据页。先确认本次交付给谁、要回答什么问题、参考的是哪份已确认的定稿。收到多个演示稿时，读标题、页序和内容，核对哪份是实际工作稿。处理一条主要结论时，先找出证据页、原始表或论文图号、比较条件和生成命令，再决定放进哪张图、哪一页或哪个章节。

长稿或多人协作时，可在证据页加一张简表，每条重要结论占一行。下面沿用仓库的合成观测例子。

| 要表达的判断 | 证据与条件 | 交付中的位置 |
| --- | --- | --- |
| A 组比 B 组早 1 小时首次达到最高观测值 | `001a` → `summary.csv`；7 条记录中 1 条缺测，并列最高值取第一次 | 组会结果页的峰值对照、论文结果段及图注 |

## 制作科研图

1. 先写一句图要解释的关系。确定最终插入宽度、单位、坐标、样本范围及不确定度。数据图追到实际结果表。流程和装置图追到规格、脚本或记录，核对箭头、接口及每步的输入与输出。
2. 用现有绘图代码，或在可用时用 [ohmyplt](https://github.com/Lee-Eee-Eee/ohmyplt) 出图。按交付格式输出 PDF、SVG 或 PNG，保留绘图源、输入和完整图。已有稿件的坐标尺度、标定条件和分组含义应随数据一起保留。生成图像可用于明确标记的概念示意，实测曲线、数值、公式及确切装置接线由资料和可复算的源码提供。
3. 把图放进目标稿件后核对一次。检查标记是否盖住曲线，坐标、字体和图例能否按实际尺寸读清。抽查图上一项数值与结果表，记录图脚本和数据版本。图和标定更新时，从证据页找出引用它的汇报页和稿段。

## 制作组会与项目汇报

用 `research-group-talk`（如已安装）组织学术内容，沿用项目的演示模板和实际交付格式。可按下表选主线。

| 场合 | 先让听众看懂 | 结尾交代 |
| --- | --- | --- |
| 组会进展 | 问题及其物理背景 → 仪器怎样生成记录 → 对照与主要证据 | 会改变判断的观测、需要组里讨论的下一步 |
| 项目进展或验收 | 目标与可验收项 → 已交付的结果与演示 → 对应指标或复核入口 | 每个待办的验证方式、负责人或预定时点 |
| 文献共读 | 论文的问题 → 采样、仪器与条件 → 带来源的原图及读法 | 哪种方法值得借鉴，应用到本项目后还需检验什么 |

按页确定主图、要讲的一句话、讲解顺序和来源。技术汇报可把仪器、信号、标定与推断分开讲。比较用相同的坐标与定义，在相关页亮出缺测、覆盖区间、样本分母或响应差异。主要判断及其适用条件放在观众能看到的位置。备注记原文图号、结果路径、版本和补充解释。

- **PowerPoint。** 用本机可用的演示制作工具生成或修订可编辑 PPTX。精细图可嵌入 SVG。需要手改图内的短标签时，用 ohmyplt 导出完整参考图、透明 SVG 和标签坐标清单，在 PowerPoint 里把选中的单行标签放成原生文本框，与底图同倍率缩放。公式、轴刻度及复杂文字保留在图层。按实际字体渲染，重开最终 PPTX 试改一处标签并检查保存后的矢量图和可编辑文字。[分层接口、合成示例与 Windows 放置脚本](https://github.com/Lee-Eee-Eee/ohmyplt/blob/main/references/slides.md)
- **Beamer。** 已有 `.tex` 或用户选用 Beamer 时，由 `beamer` 技能（如可用）配合项目指定的模板、编译器和参考文献流程。保留 `.tex`、图和书目，将终稿 PDF 渲染逐页核对。组会稿的备份页可放详细响应、样本条件和推导。[CTAN Beamer](https://ctan.org/pkg/beamer)

读一遍页序和备注，按预计时长试讲一次。渲染最后交付的文件，检查字号、裁切、图例、页脚，以及正文与备注是否引用同一版本。把已用的演示稿和关键图表链接回证据页。

## LaTeX 论文排版与编译

1. **确定编译入口。** 以期刊、会议或学校模板为准。沿用已工作的根文件、TeX 引擎、BibTeX 或 Biber 设置。缺构建入口时可用 `latexmk`。Codex 环境已提供 `latex:latex-compile` 时可用它执行编译，以实际日志为准。[Latexmk](https://ctan.org/pkg/latexmk)
2. **接上结果与书目。** 用相对路径引入图、表和 `.bib`，保留已有引用键。在 Zotero 有固定论文分类且反复手工导出时，可以用 Better BibTeX 更新对应的书目文件。把本次提交使用的 `.bib` 一起归档，让复算环境可以直接构建。核对关键文献的 DOI、版次以及引文所支持的具体结论。[Better BibTeX 自动导出](https://retorque.re/zotero-better-bibtex/exporting/auto/)
3. **从干净的输出位置编译。** 先生成必要的表和图，再编译文稿。对使用 XeLaTeX 的项目，可以从根文件所在目录运行以下命令。模板指定其他引擎时用项目自己的构建命令。

   ```sh
   latexmk -pdfxe -interaction=nonstopmode -halt-on-error -file-line-error -outdir=build main.tex
   pdffonts build/main.pdf
   pdftotext build/main.pdf build/main.txt
   pdftoppm -r 120 -png build/main.pdf build/page
   ```

4. **验收最终 PDF。** 检查编译日志中的未定义引文和交叉引用、缺字和影响排版的溢出。目检 PDF 的公式、图表、分页、字体和超链接。在正文、图注和结果表里对照一项关键数字。归档根文件、分章与宏包、书目、图表来源和已核对的 PDF。审稿修订时，可用 `latexdiff` 给两版 TeX 生成可见差异的审阅 PDF，清稿从正常入口构建。[Latexdiff](https://ctan.org/pkg/latexdiff)

## 文风调整与科学核对

先核对数值、术语、比较条件、引文和证据力度。再按读者和文体修改表达。论文让表述精确，讲稿先让听众知道图里量的是什么，再解释关系，项目报告写清交付和判断。保留作者已经认可的段落，只修读起来费力或表述不准的句子。让具体对象承担动作，把样本、单位和条件放到相关句子里，删掉重复评价和空泛过渡。

中文可用已安装的 `plain-chinese-writing`。需要诊断、局部改写或按既有文风写新稿时，可用已安装的 `sepia`，按任务选 `review`、`refactor` 或 `write`。这些技能也可以只用于单段、讲稿备注或投稿附信。没有相应技能时，直接按前一段做一遍文字检查。修完对照源稿复核数字、公式、引文、条件和结论力度，然后重新渲染受影响的页。

例如把「该变化显示校准已得到有效改善」改为「用第二天与参考温度计配对的 24 个整点读数作比较，校正后的平均绝对误差从 0.8 °C 降到 0.3 °C」，让读者看见比较对象和量级。
